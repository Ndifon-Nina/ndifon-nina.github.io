BlindSpot

Python · Flask · Security

A website security scanner. Submit a URL you own and it checks for missing security headers, exposed files (.env, .git/config), directory listing, and error leakage — then explains what to fix.

View Code
Read the full write-up

The Problem: I kept noticing websites — even my own — going up with obvious security gaps. When I researched more, I found developers often overlook the basics.

My Approach: Build a tool I'd want to use myself: paste a URL you own, get a clear list of what's missing and how to fix it.

Features: missing security headers, exposed .env / .git/config, directory listing, and error leakage checks, with fix explanations for each finding.

Security Considerations: scans only what the user submits, focuses on common misconfigurations, and reports actionable fixes rather than trying to exploit anything.

Technologies: Python, Flask, HTTP request analysis.

Challenges: deciding which checks matter most and explaining each finding simply instead of dumping raw responses.

What I Learned: how many default configurations are insecure, and how small fixes (a single missing header) can change a site's risk level.

Status: Completed — public deployment in progress.

MoMoSafe237 — Scam Reporting Platform

Python · Flask · SQLite · Security

Mobile money scam detection for Cameroon: check a number against reports, analyze a message, report a scammer, and dispute wrong reports. Includes rate limiting, login protections and an admin review system.

View Code
Read the full write-up

The Problem: When I got into cybersecurity, I realized mobile money scams have become rampant in Cameroon — mostly because people aren't aware, and there's no common place to check a suspicious number or message.

My Approach: Build a central platform where anyone can check a number or message, report a scammer, and see what others have reported.

Features: number lookup, message analysis, scam reporting, wrong-report disputes, and an admin review system to keep reports credible.

Security Considerations: rate limiting on lookups and reports, login protections, an admin approval flow, and protections against abuse of the dispute process.

Technologies: Python, Flask, SQLite, HTML/CSS.

Challenges: making it trustworthy — anyone can report, so the admin review and dispute system had to stop false reports while staying fair.

What I Learned: that a security tool's value depends on how well it handles human misuse, not just technical threats.

Status: Completed locally · public deployment in progress.
